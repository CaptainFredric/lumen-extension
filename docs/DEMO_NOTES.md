# Public demonstration boundaries

The landing page uses a light inspection desk composition to separate the
extension screenshot, live fixture, workflow instructions, and installation.

## Bug Garden

Open `bug-garden.html` in a normal Chrome tab with Lumen loaded. Run responsive
screenshots at 1280, 1024, and 430 CSS pixels. Desktop uses the current window;
resize it to 1280 for this example. The fixture is static, uses fictional
details, and sends no requests for payment or form submission.

The coupon overlaps the address between 601 and 1100 pixels. Below 601 pixels,
the order card clips its oversized continue button. These are intentionally
seeded faults. The extension's default tablet and mobile widths are 1024 and
430 pixels; the landing demo uses those same widths.
Lumen does not automatically diagnose them. The landing page
iframe displays the source HTML, not screenshots generated by the extension.

Enable optional automatic redaction to test `jane@example.test`, inspect the
result, annotate the mobile issue, and export. The originals ZIP and annotated
image exports are separate outputs today.

`npm run smoke:site` asserts iframe viewport dimensions and defect geometry at
all three widths, alongside five responsive landing widths, route isolation,
asset availability, keyboard focus, preview zoom, and JavaScript failure modes.
Install test prerequisites with `npm ci` and `npx playwright install chromium`.
These browser geometry tests do not establish extension capture reliability.

## Existing evidence

`assets/garden-desktop.png`, `garden-tablet.png`, and `garden-mobile.png` are
completed PNG downloads from the loaded extension. `garden-result.png` shows
that run in Capture Result. `garden-run.json` preserves the run's coverage,
redaction count, extracted context, dimensions, and local library identifier.
The harness uses a loopback server and a temporary copy with broad host access
because an extension page initiates the run instead of Chrome's toolbar gesture.
It exercises the real capture worker, content script, stitching, downloads,
storage, and Result UI. It does not verify a stock Chrome toolbar installation.

Reproduce with `npm ci`, `npx playwright install chromium`, then
`npm run proof:garden` on a desktop display. Linux needs a virtual display wide
enough for a 1280 CSS pixel window. Temporary profiles and downloads are removed
in `finally`; only the five published proof files are retained. Redaction must
still be visually reviewed. All displayed personal details are fictional.

Earlier `capture-run-*` assets remain for historical links and internal regression
work. They are no longer used by the landing page.
